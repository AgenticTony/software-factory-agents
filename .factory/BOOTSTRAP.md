# Bootstrap ledger

Until `factory approve` exists (F-04), nothing can legally write `.factory/tasks.json`, so its statuses stay `draft`. Progress during the bootstrap is recorded **here** instead, one entry per work order, with evidence.

F-04 AC-4 reconciles this ledger into `tasks.json`: each entry is approved and set to its final status through the normal state machine. After that, this file is frozen.

Entries record evidence, not claims. Each criterion is marked proven, pending, or not met.

## F-03 — State machine and picker

Red-first: the suite failed on the missing `factory.state` module before implementation. - **Design notes:** TASK-CONTRACT §3 as an explicit 23-edge `ALLOWED_TRANSITIONS` table; the eight `X -> draft` edges exist solely for "contract changed" (§2), with `demote_changed_contracts()` as their caller — a demoted task needs human re-approval (F-04), so it can never auto-retry. `not_buildable` has no outgoing edges (importer sets it at creation). - **Review-round changes (all 10 findings):**
  - **Concurrent writers** (reproduced): `save()` now takes an exclusive `flock` on `tasks.json.lock` (never renamed, so it's a stable lock point), re-reads the queue under it, and refuses with `ConcurrentWriteError` if the file changed since load — `factory loop` and a human `factory approve` can no longer lose each other's writes. Replaced with a **run lease**: an OS `flock` taken by `begin_run()` before the `ready → in_progress` transition and held for the session's life. `reclaim_abandoned()` acts only when the lease is free. Proven by `test_reclaim_never_takes_a_live_run`, `test_reclaim_frees_a_crash_before_the_first_attempt`, `test_begin_run_refuses_a_second_concurrent_run`, and `test_lease_is_freed_when_the_holding_process_dies` (a real subprocess exits via `os._exit` while holding the lease).

  - **`ensure_ascii=False`** (reproduced): the queue keeps literal em-dashes/arrows; no escape-noise diffs.
  - **Duplicate task ids** now rejected in `validate_queue` with a readable error.
  - **`StateError`/`TransitionError`/`ConcurrentWriteError` subclass `ContractError`** so `except ContractError` handlers catch state failures too.
  - **PR rejection:** `in_review → in_progress` (fix round) edge.
  - **Dependency drift:** `ready → blocked` edge + `sync_readiness()` reconciling both directions; cross-repo deps keep a task blocked.
  - **Picker O(n²):** the id index is built once per `pick_next` call.

## F-05 — Clone manager and sandbox

- **Commits:** `feat/f05-clone-sandbox` → PR (this one). Red-first: the suite failed on the missing `factory.runs` module before implementation.
- **Built:** 2026-10-16. Interactive session, then this ledger entry.
- **Design notes:** new `factory/runs.py` (clone manager) + `factory/sandbox.py` (srt integration), built to the owner's mid-session direction: **srt itself, not a hand-rolled Seatbelt wrapper**.
  - **srt pinned three ways:** `package.json` pins `@anthropic-ai/sandbox-runtime` at exactly `"0.0.79"` (no `^`/`~`), the committed `package-lock.json` freezes the install (CI and the Mac both run `npm ci` from it), and `ensure_srt()` runs `srt --version` before anything is sandboxed — any value other than `0.0.79` refuses with the fix in the message. `run_sandboxed()` calls it on every spawn; F-06/F-10 will also call it at session/loop start. `FACTORY_SRT_BIN` overrides the binary path for tests (fakes must still report the pin or they're refused).
  - **Settings from the profile** (`build_settings`, written by `write_settings` next to the runs root under `<factory_root>/sandbox/`): `filesystem.allowWrite = [run_dir]` only; `denyRead` = holdouts root, `~/.ssh`, `~/.config/gh` and the **whole runs root** (stricter than "other projects": sibling runs of the same project are denied too), with `allowRead = [run_dir]` re-allowing the run's own tree (allowRead beats denyRead per srt semantics); `network.allowedDomains` = model endpoint hostname (URL or bare host accepted) + `docs_allowlist` + `network_allowlist`, `deniedDomains: []` (srt requires the key and refuses invalid files rather than falling back to defaults — verified empirically).
  - **Env, two layers** (AC-4): `sandbox_env()` builds a minimal allowlist env (PATH/HOME/LANG/TZ + run-dir TMPDIR + scrubbed extras) so an interactive orchestrator shell can't leak into a session; `scrub_env()` drops the structural GitHub token names, every `GH_*`/`GITHUB_*` variable, and caller-named keychain-derived names (the Z.ai model token is deliberately not on any list — it is the one secret the sandbox holds). Backstop: the settings file denies the same names via `credentials.envVars` (`{"mode": "deny", "name": ...}`), enforced by srt even when an unscrubbed env is handed straight to it — proven by invoking srt directly with a leaky env in `test_ac_4`.
  - **TMPDIR points inside the run dir** (`<run_dir>/.tmp`): writes are allowed nowhere else, and tools that need scratch (pip builds, the macOS python xcrun shim) would otherwise break.
  - **Command transport:** `srt -c <shlex.join(cmd)>`. The variadic form joins argv naively and mangles quoting (reproduced); `-c` takes one command string verbatim, so argv survives the shell round trip exactly.
  - **Clone manager:** `create_run()` runs the WO's exact command (`git clone --filter=blob:none` from the local repo via `file://` URI), optionally detach-checkouts a ref — resolved to a commit via `ref` → `origin/<ref>` first, because a branch that exists only as a remote ref sends `checkout --detach` down git's DWIM branch-creation path, which rejects `--detach` (reproduced on git 2.50) — seeds a warm dependency cache (`shutil.copytree` into the run dir), and returns the `RunDir`. `cleanup_run()` removes clone + settings file and is idempotent. Run ids: `<UTC stamp>-<6 hex>`, created under `runs/<project>/`.
  - **Known local-git behaviour, recorded:** on this Mac's git 2.50 (Homebrew), the local `file://` server ignores the blob filter ("filtering not recognized by server, ignoring") while git still records `remote.origin.promisor=true` + `partialclonefilter=blob:none`. The command is exactly the WO's; a fully-materialised clone is still correct, just not lazy.
  - **CI (owner decision, up front):** sandbox tests RUN on Ubuntu, never skipped. The workflow installs `bubblewrap socat ripgrep`, lifts Ubuntu 24.04's AppArmor unprivileged-userns block (`sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0`) before pytest, and installs srt from the committed lockfile (`npm ci` + setup-node 22). There is no skip mechanism anywhere: locally a missing srt fails `ensure_srt` (and the tests) with the fix in the message; on CI a broken stack is a red run. `test_ac_3` makes a live, unauthenticated HTTPS request to `api.z.ai` from inside the sandbox (connection success only, no credentials); a Z.ai outage is a labelled CI failure, not a sandbox bug — the assertion message says so and the example.com control in the same test distinguishes the two.
- **AC-1** proven: `tests/test_f05.py::test_ac_1` — inside a real srt sandbox: write inside the run dir succeeds (and reads back); writes to the factory root outside the run dir and to `/tmp` raise EPERM; the target files don't exist afterwards.
- **AC-2** proven: `test_ac_2` — a real read attempt on `<factory_root>/holdouts/scenario.md` raises EPERM, while a control read inside the run dir succeeds (the denial is targeted, not a blanket read-block).
