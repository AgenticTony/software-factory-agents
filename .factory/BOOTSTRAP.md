# Bootstrap ledger

Until `factory approve` exists (F-04), nothing can legally write `.factory/tasks.json`, so its statuses stay `draft`. Progress during the bootstrap is recorded **here** instead, one entry per work order, with evidence.

F-04 AC-4 reconciles this ledger into `tasks.json`: each entry is approved and set to its final status through the normal state machine. After that, this file is frozen.

Entries record evidence, not claims. Each criterion is marked proven, pending, or not met.

## F-03 — State machine and picker

Red-first: the suite failed on the missing `factory.state` module before implementation. - **Design notes:** TASK-CONTRACT §3 as an explicit 23-edge `ALLOWED_TRANSITIONS` table; the eight `X -> draft` edges exist solely for "contract changed" (§2), with `demote_changed_contracts()` as their caller — a demoted task needs human re-approval (F-04), so it can never auto-retry. `not_buildable` has no outgoing edges (importer sets it at creation). - **Review-round changes (all 10 findings):**
  - **Concurrent writers** (reproduced): `save()` now takes an exclusive `flock` on `tasks.json.lock` (never renamed, so it's a stable lock point), re-reads the queue under it, and refuses with `ConcurrentWriteError` if the file changed since load — `factory loop` and a human `factory approve` can no longer lose each other's writes. The append-only check now runs against the queue re-read from disk, not the stale snapshot.

Replaced with a **run lease**: an OS `flock` taken by `begin_run()` before the `ready → in_progress` transition and held for the session's life. `reclaim_abandoned()` acts only when the lease is free. Proven by `test_reclaim_never_takes_a_live_run`, `test_reclaim_frees_a_crash_before_the_first_attempt`, `test_begin_run_refuses_a_second_concurrent_run`, and `test_lease_is_freed_when_the_holding_process_dies` (a real subprocess exits via `os._exit` while holding the lease).

  - **Duplicate task ids** now rejected in `validate_queue` with a readable error.
  - **`StateError`/`TransitionError`/`ConcurrentWriteError` subclass `ContractError`** so `except ContractError` handlers catch state failures too.
  - **PR rejection:** `in_review → in_progress` (fix round) edge.
  - **Dependency drift:** `ready → blocked` edge + `sync_readiness()` reconciling both directions; cross-repo deps keep a task blocked.

### F-09 owner review round 2 (PR #19; 1 new finding — fixing round-1 finding 8 let the reviewer WRITE the repo it reviews; fixed on this PR, red-first under `test_review9*`)

- **The hole (owner-reproduced; re-verified here at the sandbox layer against `51b230c`):** finding 8's `bypassPermissions` made the reviewer's Bash headless — but both seats shared the same srt settings, whose `allowWrite: [<run_dir>]` made the whole run dir writable. Under the reviewer's settings, `echo broken > src/app.py` exited 0 (file overwritten), a `python -c` write exited 0, and `git add -A; git commit` exited 0 with HEAD moved — the docstring's "reads, never writes" was false. A reviewer that can write the repo can "fix" the code, watch its own fix pass, and report PASS on a diff that isn't the implementer's; its commit would ride the branch F-10 pushes.
- **Fix layer 1 — read-only reviewer sandbox:** `build_settings(..., read_only=True)` narrows `allowWrite` to exactly the git-excluded `.home`/`.tmp` scratch dirs (created up front so the settings are self-sufficient); the `.git` denyWrite entries stay for both modes; cache writes tools make in the tree (`__pycache__`, `.pytest_cache`) fail closed — Python and pytest degrade to warnings on unwritable caches, so read-only checks still run. `run_session_sandboxed` passes `read_only=(seat == "reviewer")`. Proven by `test_review9_reviewer_sandbox_is_read_only` (real srt: overwrite-source, sed-a-test, python-c-write and git-commit probes all denied, files/HEAD unchanged, `.home`/`.tmp` scratch still writable) and `test_review9_implementer_sandbox_still_writes` (the guard is the reviewer's, not global). `test_review9_session_builds_read_only_settings_for_the_reviewer` pins the wiring (`read_only` True for the reviewer build, False for the implementer's).
- **Fix layer 2 — orchestrator-side integrity backstop (per the owner's two-part direction):** after EVERY reviewer session, hardened-git compares `(rev-parse HEAD, status --porcelain)` against a baseline taken before the session (the scratch dirs are mkdir'd before the baseline so their untracked presence can never masquerade as a mutation). Any difference → the workspace is restored (`git reset --hard <baseline-head>` + `git clean -fd`, no `-x`, so excluded scratch survives) and the record is forced to `failed` with reason `reviewer_mutated_workspace` — the verdict text of a reviewer that changed the code is kept for forensics but never trusted. This is the backstop for any future path that lets a write through (a settings bug, an srt regression). Proven by `test_review9_workspace_integrity_checked_after_review` (a faked session commits + drops an untracked file → failed/`reviewer_mutated_workspace`, HEAD restored, tree clean, smuggled file gone) and `test_review9_clean_review_passes_the_integrity_check` (a quiet review returns untouched; the implementer seat is never subjected to the guard).
