# Bootstrap ledger

Until `factory approve` exists (F-04), nothing can legally write `.factory/tasks.json`, so its statuses stay `draft`. Progress during the bootstrap is recorded **here** instead, one entry per work order, with evidence.

F-04 AC-4 reconciles this ledger into `tasks.json`: each entry is approved and set to its final status through the normal state machine. After that, this file is frozen.

Entries record evidence, not claims. Each criterion is marked proven, pending, or not met.

## F-03 — State machine and picker

Red-first: the suite failed on the missing `factory.state` module before implementation. - **Design notes:** TASK-CONTRACT §3 as an explicit 23-edge `ALLOWED_TRANSITIONS` table; the eight `X -> draft` edges exist solely for "contract changed" (§2), with `demote_changed_contracts()` as their caller — a demoted task needs human re-approval (F-04), so it can never auto-retry. `not_buildable` has no outgoing edges (importer sets it at creation). - **Review-round changes (all 10 findings):**
  - **Concurrent writers** (reproduced): `save()` now takes an exclusive `flock` on `tasks.json.lock` (never renamed, so it's a stable lock point), re-reads the queue under it, and refuses with `ConcurrentWriteError` if the file changed since load — `factory loop` and a human `factory approve` can no longer lose each other's writes. The append-only check now runs against the queue re-read from disk, not the stale snapshot.

Replaced with a **run lease**: an OS `flock` taken by `begin_run()` before the `ready → in_progress` transition and held for the session's life. `reclaim_abandoned()` acts only when the lease is free. Proven by `test_reclaim_never_takes_a_live_run`, `test_reclaim_frees_a_crash_before_the_first_attempt`, `test_begin_run_refuses_a_second_concurrent_run`, and `test_lease_is_freed_when_the_holding_process_dies` (a real subprocess exits via `os._exit` while holding the lease).

  - **Duplicate task ids** now rejected in `validate_queue` with a readable error.
  - **`StateError`/`TransitionError`/`ConcurrentWriteError` subclass `ContractError`** so `except ContractError` handlers catch state failures too.
  - **PR rejection:** `in_review → in_progress` (fix round) edge.
  - **Dependency drift:** `ready → blocked` edge + `sync_readiness()` reconciling both directions; cross-repo deps keep a task blocked.

- **Built:** 2026-10-18.
- **Design notes:**
  - **The run (`factory/orchestrator.py`):** reclaim orphans → pick → peak-window check → lease + `in_progress` → clone at the default branch → branch `factory/<slug>-<run_id>` → rounds. A round: implementer session (contract + progress log 1..N in the prompt) → the orchestrator commits the working tree with hardened git (`--no-verify`, factory identity) and **voids the round** (`history_rewritten`) if HEAD no longer descends from the base — the agent owns its clone's history, the orchestrator never pushes a rewrite → fresh clean clone at head → L0 + L1 through the sandboxed runner → L2 reviewer session → FAIL's numbered findings append to the progress log and the next round starts. Escalations per VALIDATOR-SPEC: L0 protected/new-dependency/risk-path hits escalate immediately (`needs_human`, one attempt, most-severe-first); quota/429 **aborts** the attempt (excluded from the budget), re-queues the task and stops the loop; `attempts_exhausted` after `budget.max_attempts` (counted across runs per slice, `aborted` excluded); the wall-clock budget spans a run's implementer+reviewer seconds and escalates `budget_exhausted` rather than starting a session that can't finish. A crashed orchestrator re-queues an `in_progress` task with no recorded outcome (the aborted-run edge), so the queue can't wedge.
  - **Project commands are untrusted (AC-11):** `factory/gates.py` gained the `CommandRunner` seam; `run_l0`/`run_l1` take `runner=`; the orchestrator passes `sandboxed_runner(clean_run_dir, settings)` — every setup/lint/typecheck/test/test_ref command runs through `run_sandboxed` under F-05 settings for the clean clone, and the runner refuses any repo that isn't its own run dir. The gates' default stays the unconfined `run_command` for fixture tests, documented as such at the seam.
  - **The push fence (AC-13, `factory/publish.py`):** `push_branch` pushes exactly one ref by explicit `refs/heads/X:refs/heads/X` to the profile's remote **URL** (never a configured remote name, so no `remote.*.push`/mirror config applies), `--no-follow-tags`, no force. It refuses — before any git process starts — the default branch, anything outside the `factory/` namespace, any branch the run didn't create (a `created` set), and anything that isn't a plain branch name (refspec syntax, `+`, `HEAD`, `..`, `.lock`). `gh_pr_create` opens the PR (body via a temp file outside every clone — argv limits and `ps`); the factory never merges (AC-5's grep test pins it). `gates.git` and L1's `cat-file` are hardened too: after F-10, **every** orchestrator-side git call carries `GIT_HARDENING`.
  - **The PR body (AC-7/8/9/14, `factory/prbody.py`):** six sections — Summary, Evidence, Merge Danger, Contract, Validator report, How to revert — and `check_pr_body` refuses to open a PR missing or duplicating any. Evidence/Door/Blast Radius/How-to-revert are built from validator facts only (L1's per-ref red_reasons on base; risk flags + matched `paths.risk` globs or `contained`; Door `one-way` when the task carries `migration`/`deploy`/`external_service`/`payments`/`privacy`, else `two-way`; per-Door revert text naming each flag a revert can't undo). The implementer's account rides below as inert fenced text; command tails shrink in three passes to fit GitHub's 65,536-char body limit, then the gate still applies.
  - **The progress log (AC-10, `factory/progress.py`):** one append-only jsonl per task under `<factory_root>/progress/<project>/<task>.jsonl` — outside every clone, fcntl-locked, hash-chained (each entry carries its number and the sha256 of the previous line; there is no edit API). Every new session — re-queued run or future fix round — receives entries 1..N rendered read-only in its prompt; rewriting, dropping or reordering an earlier entry raises on read and on the next append.
  - **Cleanup (AC-12):** `cleanup_run` runs in `finally` for both run dirs (work clone + each gate clone) on every outcome — PR opened, `needs_human`, quota stop, exception. `reclaim_runs` removes every run dir of the project **under the new `idle_lease`** (no live run can race it; a killed run's dirs are orphans the moment the lease is free) plus stray `-runner`/`-scratch` siblings under `<root>/sandbox/`, at the start of every `run_once` — so `loop` reclaims what a killed run left.
  - **The peak window (AC-4, `factory/config.py`):** `<factory_root>/config.yaml`, default `Europe/Stockholm` Mon–Fri 08:00–12:00 (end exclusive) — the owner's working hours, from config not code. Checked before the implementer session *and* before the reviewer session (a window reached mid-run stops before the next session and re-queues). Malformed config is a `ConfigError`, not a default: a silently mis-parsed window would spend quota at exactly the wrong hours. DST is real (ZoneInfo; the boundary test crosses Stockholm's fall-back).
  - **CLI:** `factory run` / `factory loop` are real subcommands. Exit codes: 0 = PR opened / idle / peak window, 1 = `needs_human`, 3 = quota stop, 2 = the orchestrator itself failed (task re-queued, run dirs removed first) — known failures print a message, not a traceback.
